## 1. 产品定位与一句话

### 官方品牌名

**deepdog**（小写，正文中不要写成 DeepDog / Deep Dog）

### 官方 Slogan（落地页现用，直接可用于片头）

> **Your next 10 hires won't be human.**
> 你接下来要招的 10 个人，都不是人。

### 官方副标题（落地页现用）

> deepdog is an open-source platform that turns coding agents into real teammates. Assign tasks, track progress, compound skills — manage your human + agent workforce in one place.
>
> deepdog 是一个开源平台，把编码智能体变成真正的队友。分派任务、追踪进度、沉淀技能——在一处管理你的「人类 + 智能体」混合团队。

### 电梯陈述（30 秒版）

> 编码智能体已经很会「干活」了，但没人管它们。
> deepdog 补上的是**管理层**：任务队列、团队协同、技能复用、算力监控，以及一个能看到每个智能体正在干什么的统一视图。
> 一句话——**它是你所有 AI 智能体的项目经理。**

### 定位类比

| 反向定位 | deepdog **不是** AI 工具，而是**人 + AI 协作的任务管理平台** |
| 元数据定位 | Internal AI Workbench — 面向任务协同、智能体执行与团队运营的内部 AI 工作台 |

## 2. 解决的问题

### 直接使用编码智能体的四个痛点（片头冲突段可直接用）

1. **每次都要复制粘贴 prompt** —— 没有任务沉淀，重复劳动。
2. **必须盯着终端** —— 你成了智能体的保姆，不敢离开。
3. **没有跨任务记忆** —— 每次从零开始，上次的上下文全丢。
4. **多智能体并行时没有全局视图** —— 谁在干什么、卡在哪，一片黑箱。

### deepdog 的对应解法（转折段）

| 痛点 | 解法 |
|---|---|
| 复制粘贴 prompt | 智能体和人**共用同一个 issue 看板**，派单即开工 |
| 盯终端 | **完整任务生命周期** + 实时进度流，可以睡觉时让它跑 |
| 无记忆 | **会话自动恢复**——同一 (agent, issue) 复用上次 session_id 和工作目录 |
| 无全局视图 | **统一活动时间线** + Runtime 面板 + Observer 实时观测 |

## 3. 核心概念词典

> 拍摄字幕/旁白中出现这些词时，必须按此定义使用，不可混用。

| 概念 | 定义 | 一句话画面感 |
|---|---|---|
| **Workspace 工作区** | 一切资源的容器，多租户边界。issue、agent、skill、成员全隔离在其中 | 「公司」 |
| **Issue 议题** | 最核心的工作对象。可分配给人**或**智能体，完全对等 | 「工单」 |
| **Agent 智能体** | 可被指派任务的 AI 工作者。有头像、有 profile、会评论、会自己建单 | 「AI 员工」 |
| **Runtime 运行时** | 智能体实际跑在哪台机器上。一个 runtime = 一台能跑智能体的机器 | 「工位 / 算力」 |
| **Daemon 守护进程** | 用户本地的后台程序，自动发现已装的 coding CLI 并注册为 runtime，然后不停认领任务 | 「派单员」 |
| **Task 任务** | 智能体执行一次 issue 产生的一次运行（一次会话），队列化执行 | 「一次出工」 |
| **Skill 技能** | 工作区级可复用说明文档，开跑时注入工作目录让 CLI 读到 | 「员工手册 / 传承」 |
| **Squad 小队** | 智能体 + 人组成的编队，有 leader（智能体）、成员角色、小队专属 instructions | 「项目组」 |
| **Autopilot 自动驾驶** | 按 cron 定时或 webhook 触发，自动建 issue 并派给智能体 | 「自动排班」 |
| **Observer 观测器** | 观测**人类自己**在本地 AI 客户端里的会话，旁路采集并上报 | 「行车记录仪」 |
| **Session Resumption 会话恢复** | 下一次任务自动复用上次的 session_id + work_dir，上下文与文件状态全保留 | 「接着上次说」 |
| **Polymorphic Actor 多态行动者** | 几乎所有「谁做了什么」都是 `actor_type`(member/agent) + `actor_id`。这就是智能体能像人一样行动的底层原因 | 「同一套身份系统」 |

## 4. 功能全景

### 4.1 Issue 议题管理（核心工作对象）

**字段能力**：标题、富文本描述（Tiptap）、状态、优先级、自动递增编号（带工作区前缀如 `ACME-42`）、**Assignee 可为人或智能体**、**Creator 可为人或智能体**、父子 issue、所属 Project、截止日期、多标签、依赖/阻塞关系、验收标准、来源（若由 autopilot 创建会记录来源 run）。

**三种视图**：
- **List 列表**：表格，可按 status / priority / assignee / creator / project 过滤，按名称/优先级/截止日/手动位置排序
- **Board 看板**：Kanban 按状态分列，支持拖拽（拖动自动切「手动排序」模式）
- **My Issues**：三个 scope —— 分配给我 / 我创建的 / 我的智能体负责的

**交互亮点**：
- 快速创建（侧边栏单行）或富文本弹窗创建（草稿本地持久化）
- 批量多选改 status/priority/assignee/删除
- 父 issue 显示子任务完成比例**圆环**
- 订阅机制（creator / assignee / 被 @ 者自动订阅）
- emoji 反应、Pin 置顶到侧边栏、复制链接、`Cmd+K` 跳转
- **Timeline 时间线**：状态变更 + 指派变更 + 评论按时序混排

**⭐ 视频高光点**：**在评论里 `@某个智能体`，会自动生成一个新任务让它来处理。** 这是「智能体是一等公民」最直观的一帧。

### 4.2 Agent 智能体

- 有**独立 profile**：名字、头像、说明
- 指定 runtime 和 provider（跑在哪台机器、用哪个 CLI）
- 可配自定义系统 prompt、挂载 skills、独立的模型 / API Key / 环境变量 / **MCP 服务器列表**
- **自动激活三种方式**：被指派时 / 被评论时 / 被 @ 提到时
- 在 assignee 下拉里**和人并列出现**
- UI 上以差异化样式渲染（紫色底 + 机器人图标）

### 4.3 Runtime 运行时 & Daemon

- **自动探测**：daemon 首次运行扫描本机已安装的编码 CLI，逐个注册为 runtime
- **统一面板**：本地 daemon + 云端 runtime 在同一个视图，无需切换管理界面
- **实时监控**：在线/离线状态、用量图表、活动热力图
- **添加电脑**：Runtimes 页面提供「Add a computer」引导，生成部署感知的接入命令
- 心跳机制（WebSocket + HTTP 双通道）保持在线状态
- 并发上限可配（`max_concurrent_tasks`，实测默认 20）

### 4.4 Skill 技能（复利效应，最佳叙事素材）

- 技能 = 可复用的能力定义（代码 + 配置 + 上下文打包）
- **写一次，全团队每个智能体都能用**
- 智能体开跑时把挂载的 skill 内容注入工作目录，让 CLI 直接读到

**⭐ 官方复利叙事（强烈建议做成动画）**：
> **Day 1**：你教会一个智能体部署。
> **Day 30**：每个智能体都会部署、会写测试、会做 code review。
> 团队能力**指数级**增长。

### 4.5 Squad 小队（编队协作）

- 小队由**智能体 + 人**混编
- 有 **leader**（必须是智能体，带皇冠标识）
- 每个成员可设自定义 role
- 小队级 **instructions**（专属作战指令）
- 小队头像、描述可配
- **实时状态快照**：每个成员的 working / idle / offline + 当前处理的 issue
- 可在小队内直接创建新智能体并自动入队
- 支持归档

### 4.6 Autopilot 自动驾驶

- **两种执行模式**：
  - `create_issue` —— 自动建 issue 并派给智能体（支持 issue 标题模板，`{{date}}` 可插值）
  - `run_only` —— 只跑任务不建单
- **两类触发器**：cron 定时（含时区处理）/ webhook（外部 JSON 归一化为标准 envelope）
- 每次触发生成一条 `autopilot_run` 记录，可追溯
- 典型场景：**每天早上 9 点自动做一轮 bug triage**

### 4.7 Observer 观测人类会话（独有能力）

观测「人类自己在本地 AI 客户端里干活」的会话，旁路采集上报。管理页实时展示：
- **Client presence**：每个 provider 的在线/离线状态，按 daemon 分组
- **Session events**：实时事件流（provider / 事件类型 / 工具名 / 内容 / session#seq）

**⭐ 视频价值**：这是「不止管 AI，还能沉淀人类的工作过程」的杀手级差异点。

### 4.8 Chat 对话

用户与智能体的持久化多轮对话，**不依附于 issue**，独立会话线。

### 4.9 Inbox 收件箱

个人通知中心。被 @、被分配、订阅的 issue 有更新，都进这里。

### 4.10 Workbench 工作台（模板化启动）

提供 6 类开箱模板，一键预填任务草稿：
**会议（meeting）· 调研（research）· 客户（customer）· 周报（weekly）· 文档（document）· 运维（ops）**

配合 4 个状态泳道：`triage → running → review → done`

### 4.11 Project 项目

议题的高层归属，类似「里程碑 / 版本」。

### 4.12 成员、权限与协作

- 三级角色：**owner / admin / member**
- 一个用户可属于多个 workspace，不同 workspace 可有不同角色
- 邀请流程、接受邀请页
- 附件上传（拖拽/按钮，图片内联预览，S3/CloudFront 或本地磁盘）

### 4.13 Usage 用量 & Billing 计费

- **Usage**：token 用量统计与图表
- **Billing**：积分余额（credit / micro-credit）、价格档位、Stripe Checkout 下单、客户自助 Portal、交易记录、批次、充值记录

### 4.14 搜索与命令面板

`Cmd+K` 全局命令面板，支持**拼音匹配**（中文用户友好，`matchesPinyin`）。

### 4.15 CLI 与工单 MCP 工具

- CLI：`multica setup` 一条命令走完 OAuth → 起 daemon → 扫描 CLI 工具
- CLI 支持 issue 创建、metadata 读写、autopilot 管理等
- **BIOS MCP 工具**：向任意 MCP 客户端暴露 4 个工单工具 —— `bios_create_issue`（建单，带幂等键）、`bios_update_stage`（推进阶段）、`bios_report_progress`（进度留言）、`bios_link_repo`（关联仓库）
- **GitHub 自动通道**：分支名带工单号（如 `feat/web/MUL-120-auth-login`）后，建分支 → `execute`、开 PR → `verify`、merge + CI 绿 → `done + close`，**全自动无需手动汇报**

## 5. 三大技术底座（差异化护城河）

> 这三条是 deepdog 真正的技术壁垒。宣传片如果要「显专业」，就讲这三条。

### 5.1 派发任务 —— 完整任务生命周期

**生命周期**：`enqueue → claim → start → complete / fail`
**核心承诺**：**没有静默失败**，每一次状态转移都被记录并广播。

```
用户建 Issue → 服务端入队 → WebSocket 推送 task_available
                                    ↓
                          本地 Daemon 认领（claim）
                                    ↓
                    准备隔离工作目录 + 注入 skills/上下文
                                    ↓
                          启动编码 CLI 子进程执行
```

**工程亮点**（可做技术彩蛋字幕）：
- **每个 runtime 独立 poller**：一个 runtime 的网络超时不会拖慢其他 runtime
- **slot-before-claim**：先抢执行槽再认领任务，避免任务认领后等不到执行而超时
- **会话恢复**：任务执行中持久化 `session_id + work_dir`，daemon 崩溃也不丢续跑指针

### 5.2 任务实时反馈 —— WebSocket 实时进度流

```
编码 CLI 子进程
  → 结构化输出（文本 / 思考 / 工具调用 / 工具结果）
  → Daemon 每 500ms 批量聚合
  → HTTP 上报服务端
  → WebSocket 广播到前端
  → 时间线实时刷新
```

**三重保护机制**（体现工程严谨度）：
- **取消轮询**：每 5 秒检查服务端是否已取消，取消则立即终止 CLI 进程
- **执行超时**：超时后标记 `timeout`，不会挂死
- **空闲看门狗**：智能体长时间无输出**且**没有进行中的工具调用 → 判定假死并终止

**⭐ 视频呈现**：屏幕上实时滚动智能体的思考过程、工具调用、文件改动——「你能看见它在想什么」。

### 5.3 观测人类自用会话 —— 四条采集通道

deepdog 能观测你**自己**在本地 AI 客户端里的工作（不是它派的任务），有四条互补通道：

| 通道 | 原理 | 覆盖对象 |
|---|---|---|
| **进程存在检测** | 每 30 秒扫进程表，状态变化才上报 | 所有 GUI 客户端的在线/离线 |
| **文件尾随** | 增量 tail 会话 JSONL 文件 / SQLite 库，断点续传 | Codex、Hermes、OpenClaw |
| **本地 WebSocket 旁挂** | 接入客户端本地 WS 服务，只读镜像会话 | Claude Code 桌面版 |
| **Hooks / MCP 推送** | 注入 hooks 配置，客户端主动 POST 事件到本地 daemon | Claude Code、WorkBuddy |

**统一事件模型**：所有通道最终产出同一个 `ObserverEvent` 结构（`session_start / message / tool_use / tool_result / session_end`），前端用同一套渲染。

**⭐ 一句话卖点**：**「不止管 AI 干的活，还能把你自己干的活也沉淀下来。」**

## 6. 宣传片分镜脚本建议

> 总时长建议 **90–120 秒**。以下为 7 幕结构，每幕给出画面、字幕/旁白、时长。

### 幕 1 · 冲突（0:00–0:12）

- **画面**：深色终端，一个人反复复制粘贴 prompt；旁边时钟快进；深夜台灯下他还在盯屏幕。
- **字幕（快切，每条 1.5 秒）**：
  - 「复制。粘贴。等待。」
  - 「盯着终端，不敢走开。」
  - 「换个任务，上下文全丢了。」
  - 「三个智能体在跑——谁卡住了？不知道。」
- **旁白**：编码智能体已经很聪明了。可是**没人管它们**。

### 幕 2 · 品牌亮相（0:12–0:20）

- **画面**：黑屏，logo 从暗处浮现，粒子聚合成 deepdog 标识。
- **主字幕（大字，衬线体）**：
  > **Your next 10 hires won't be human.**
- **副字幕**：deepdog — 把编码智能体变成真正的队友。

### 幕 3 · 核心动作：像派给同事一样派给智能体（0:20–0:38）

- **画面**：
  1. 看板视图，鼠标点开一个 issue
  2. 点开 assignee 下拉——**人类头像和智能体头像并列出现**（智能体带紫色底 + 机器人图标）
  3. 选中智能体，issue 状态自动跳转
  4. 时间线立刻出现「已认领」→「执行中」
- **字幕**：`分派给智能体 = 分派给同事。零学习成本。`
- **旁白**：智能体有 profile、会评论、会自己建单。它不是工具，是**参与者**。

### 幕 4 · 实时反馈：你能看见它在想什么（0:38–0:56）

- **画面**：右侧面板实时滚动流——思考过程、工具调用卡片（读文件/改代码/跑测试）、文件 diff 高亮；进度不断刷新。
- **字幕（角标技术彩蛋）**：`WebSocket 实时流 · 500ms 批量聚合`
- **旁白**：完整生命周期——入队、认领、启动、完成或失败。**没有静默失败。** 卡住了它会主动举手。
- **收尾画面**：切到深夜，屏幕仍在滚动。字幕：`Set it and forget it — 它在你睡觉时工作。`

### 幕 5 · 复利：技能沉淀（0:56–1:14）

> **这是全片情绪最高点，建议做成动画。**

- **画面**：
  1. `Day 1` —— 一个技能卡片「部署到 staging」被创建，一条线连到 1 个智能体
  2. 时间轴推进，技能卡片增加：「写迁移」「Review PR」「跑测试」
  3. `Day 30` —— 线条爆炸式增殖，**所有**智能体都连上**所有**技能，形成网状发光图
- **字幕**：
  > Day 1：你教会一个智能体部署。
  > Day 30：每个智能体都会部署、写测试、做 code review。
- **旁白**：写一次，全团队复用。你的团队能力，是**指数级**增长的。

### 幕 6 · 全局掌控：Runtime + Squad + Observer（1:14–1:34）

- **画面（三段快切）**：
  1. **Runtimes 面板**：多台机器卡片、在线绿点、用量图表、活动热力图
  2. **Squad 详情**：智能体+人混编，leader 皇冠标识，成员状态实时跳动（working/idle）
  3. **Observer 页**：presence 列表 + 实时 session event 流滚动
- **字幕**：`一块面板，管完所有算力。` → `编队作战。` → `连你自己的会话也一起沉淀。`
- **旁白**：本地机器、云端算力，统一视图。自动探测你已装好的编码工具，逐个注册。

### 幕 7 · 信任与行动（1:34–2:00）

- **画面**：GitHub 仓库页 star 数上涨 → Docker/K8s 图标 → 桌面端 + Web 端 + iOS 端三屏并列。
- **字幕（逐条打出）**：
  - `完全开源，每一行可审计`
  - `自托管任你部署 — Docker / 单二进制 / K8s`
  - `代码永不经过 deepdog 服务器`
  - `不锁厂商 — 自带 LLM、可换后端`
- **旁白**：执行发生在**你自己的机器**上。deepdog 只协调任务状态和广播事件。
- **收尾大字**：
  > **Hire your first AI employee in the next hour.**
  > deepdog · Open source

## 7. 视觉与调性规范

### 调性

| 维度 | 要求 |
|---|---|
| 整体气质 | 冷静、专业、克制的科技感。**不要**浮夸、不要爆炸特效、不要廉价 AI 音效 |
| 参照系 | Linear / Vercel / Stripe 的产品片风格 |
| 情绪曲线 | 压抑（痛点）→ 明亮（解法）→ 高潮（复利）→ 沉稳可信（开源） |

### 色彩

- **主背景（深色场景）**：接近纯黑的深蓝黑 `#05070b`（落地页 hero 实际用色）
- **浅色场景背景**：纯白，文字用 `#0a0d12`
- **智能体标识色**：紫色系（与产品内智能体渲染一致）
- **状态色**：在线绿、离线灰
- **禁止**：霓虹渐变堆叠、彩虹色、赛博朋克紫粉俗套配色

### 字体

- **大标题**：衬线体（落地页 hero 用 serif，气质关键）
- **正文 / UI**：无衬线
- **代码 / ID / 数字**：等宽字体（`font-mono`，产品内大量使用）

### 音乐与音效

- 低频铺底 + 渐进节奏，第 5 幕（复利）达到峰值
- 音效克制：只在关键交互（派单、状态跳转）加轻微 UI 音
- **不要**科幻电影式的重低音轰鸣

### 产品画面素材

- 优先使用**真实产品截图/录屏**，不要凭空画假 UI
- 现成素材位置：`apps/web/public/images/landing-hero.png`（看板视图主视觉）、`feature-bg-*.jpg`（特性区背景）
- 界面中若出现工单号，使用 `MUL-` 或 `ACME-` 形式；**不要**编造真实客户名

## 8. 事实准确性红线

> ⚠️ 交给视频 Agent 时请连同本章一起交付。以下每条都可能被真实用户当场验证。

### 必须准确的事实

| 项 | 正确表述 | 常见错误 |
|---|---|---|
| 品牌名 | **deepdog**（全小写） | ~~DeepDog~~ / ~~Deep Dog~~ / ~~Multica~~（旧内部名，代码包名遗留，**不可对外使用**） |
| 支持的编码工具数 | 官方口径 **12 个** | 不要说「支持所有 AI 工具」 |
| 12 个工具名单 | Antigravity, Claude Code, Codex, Cursor, Copilot, Gemini, Hermes, Kimi, Kiro CLI, OpenCode, OpenClaw, Pi | 不要漏写或臆造 |
| 是否训模型 | **不训模型**，是调度器 / 管理层 | ~~「deepdog 的 AI 模型」~~ |
| 代码安全 | 执行在**用户自己的机器或自有云**，代码**不经过** deepdog 服务器 | 不要说「上传到云端分析」 |
| 部署形态 | 云托管 + 自托管（Docker Compose / 单二进制 / K8s）双选 | 不要说「仅 SaaS」 |
| 客户端 | Web（Next.js）+ 桌面（Electron）+ iOS（Expo） | 不要宣称 Android 版 |
| 开源 | 完全开源、可审计、可自托管 | 不要说「部分开源」 |
| 智能体上限 | 开源版**无人为上限**，取决于硬件 | 不要编造具体数字 |

### 严禁出现的内容

- ❌ **编造任何量化战绩**：如「效率提升 300%」「已服务 10000 家企业」「节省 80% 工时」——仓库内**没有**任何此类数据支撑。
- ❌ **编造客户 logo / 名人推荐 / 媒体背书**。
- ❌ **编造融资、团队规模、公司历史**。
- ❌ **把 Observer 说成「监控员工」**。它的定位是**沉淀工作过程与上下文**，不是监视工具。措辞用「观测 / 沉淀 / 留痕」，避免「监控 / 监视」。
- ❌ **承诺未实现的能力**：如「自动修复所有 bug」「无需人工review」。
- ❌ 使用旧内部代号 `Multica`（代码里的 `@multica/*` 只是历史包名）。
